# OMP UI в OMPWeb

OMP UI — локальный рендерер завершённых блоков `omp-ui` в Markdown. Использует существующие React-компоненты и CSS-токены OMPWeb, без новых зависимостей. Это не пакет `dsh-genui` и не совместимый с ним протокол.

## Использование

Попросите агента: «Покажи эти данные карточкой OMP UI», «Сделай OMP UI таблицу и график» или «Подготовь форму OMP UI». В новых сессиях доступен скилл `omp-ui`; его исходник и полный каталог — [SKILL.md](../skills/omp-ui/SKILL.md).

Минимальный пример с демонстрационными, не реальными показателями:

```omp-ui
{
  "type": "panel",
  "title": "Демонстрационный отчёт",
  "items": [
    {"type": "text", "text": "Эти значения показывают формат, а не состояние инфраструктуры."},
    {"type": "stat", "label": "Доля", "value": 84.17, "unit": "%", "tone": "success"},
    {"type": "chart", "title": "Изменение", "kind": "line", "data": [{"label": "A", "value": -10}, {"label": "B", "value": 0}, {"label": "C", "value": 25}]},
    {"type": "action", "label": "Объяснить данные", "message": "Объясни демонстрационные значения в этой карточке. Не выполняй изменения."}
  ]
}
```

Каталог: `panel`, `text`, `stat`, `keyvalue`, `table`, `steps`, `chart`, `action`, `form`. Графики: bar/line с SVG, включая отрицательные, нулевые и одиночные значения; исходные данные доступны в раскрываемой таблице. Формы: text/number/date/select/checkbox/range. Необязательное пустое числовое поле отправляется как `null`, checkbox — как boolean, введённое число — как number. Range по умолчанию: 0–100, шаг 1.

При стриминге блок остаётся кодом. Некорректный JSON, неизвестное свойство/тип или превышение лимита показывают ошибку и исходник; валидные соседние компоненты не исполняются частично. Исходник можно посмотреть и скопировать.

Лимиты: 50 000 символов исходника, 100 компонентов, 6 уровней вложенности, 4000 символов в строке, 200 строк/20 столбцов таблицы, 200 точек графика, 20 полей формы и 100 вариантов select. Имена полей уникальны; опасные имена вроде `__proto__` запрещены.

## Действия и безопасность

- Данные рендерятся как React-текст. Нельзя задавать HTML, JavaScript, URL, функции, выражения или RPC-команды.
- Кнопка/форма сначала показывает точный текст сообщения. Только явное подтверждение отправляет его агенту.
- Сообщение всегда начинается с `OMP UI — действие пользователя:`. Начальные `!` и `/` в сгенерированном тексте не превращаются в shell/slash-команду.
- Действия доступны только в тексте основного ассистента своей подключённой сессии. В пользовательском сообщении, tool/custom/thinking-блоках, субагентных диалогах и файловом превью карточки остаются read-only.
- Холодная история без подключённого runtime остаётся read-only. Подключите её обычным сообщением в composer; карточки смогут отправлять запросы после успешного подключения. Во время загрузки, потери SSE, внешнего запуска или просмотра исторической ветки действия отключены.
- Свободный агент получает обычный prompt; занятый — follow-up. Рендерер не создаёт новый транспорт и не вмешивается в draft composer.
- Повторный клик во время отправки не создаёт второй запрос. Смена владельца/исходника или потеря capability закрывает подтверждение; введённые значения сохраняются при переподключении той же сессии. Уже отправленный запрос отменить сменой вкладки нельзя.
- Пароли, ключи, токены и другие секреты в формы не вводятся. Кнопка не является разрешением на инфраструктурную мутацию; read-only политика стендов действует всегда.
- Ошибка нового рендерера изолирована границами одного блока и не должна скрывать остальную переписку.

Обычный Markdown-санитайзер, Mermaid, KaTeX, ссылки/изображения и существующее HTML-превью файлов не ослаблены. Для произвольного самостоятельного мини-приложения используйте HTML-файл в штатном FileViewer, а не `omp-ui`.

## Почему такое решение

Сравнены первичные источники:

- [dsh-genui](https://github.com/omdsh-dev/dsh-genui) и [его каталог](https://raw.githubusercontent.com/omdsh-dev/dsh-genui/main/SKILL.md): удобный набор компонентов и JSON-fence, но плагин связан с DSH-host API.
- [Google A2UI](https://a2ui.org/) и [семантика действий](https://a2ui.org/concepts/actions/): декларативный UI и явное отделение локальных взаимодействий от действий агента, но отдельный протокол surface/data/lifecycle здесь не нужен.
- [Vercel json-render](https://github.com/vercel-labs/json-render/blob/main/README.md): ограниченный каталог и проверка данных, но готовый стек добавляет зависимости и механизм JSON-патчей.

Выбран небольшой собственный каталог в существующем Markdown-рендерере OMPWeb. Чужой исходный код не переносился; зависимости и обычный формат сообщений не менялись.

## Развёртывание без прерывания сессий

Рабочий `ompweb.service` продолжает владеть API и процессами агентов на 127.0.0.1:30177. Новый `ompweb-ui.service` обслуживает только страницы и статические ресурсы на 127.0.0.1:30178. Его unit: [deploy/ompweb-ui.service](../deploy/ompweb-ui.service).

В двух существующих OMPWeb-сайтах Caddy `/api/*` направлен на 30177, остальные запросы — на 30178. Обе существующие защиты доступа, Host/X-Forwarded-Proto, TLS-настройки и остальные сайты Caddy сохранены. Фронтенд использует существующие EnvironmentFile и cookie-signing secret без их копирования/изменения.

`OMP_WEB_FRONTEND_ONLY=1` запрещает прямые API-запросы к фронтенд-процессу с 503 и отключает его OMP warmup/auto-resume. Поэтому второй процесс не становится вторым владельцем агентных сессий. Прямой порт 30178 не является самостоятельным рабочим входом: открывайте обычный HTTPS-адрес через Caddy.

Старая npm-установка и её скомпилированные файлы не заменялись. Старые immutable static assets добавлены в новый frontend, чтобы уже открытые вкладки могли догрузить свои чанки. В исходниках сохранены прежнее исправление списка сессий и authenticated PWA manifest.

Обновляйте эту локальную сборку вручную; обычная установка новой npm-версии не обновляет её компоненты. Не пересобирайте `.next` под работающим frontend-процессом: остановите только `ompweb-ui.service`, выполните проверки/сборку и снова запустите его. Сессии основного API-процесса продолжат работать, но загрузка новых страниц на время остановки frontend будет недоступна. Обновление backend также требует проверки совместимости с локальным frontend.

Откат маршрутов: приватная копия прежнего Caddyfile находится в `/root/.omp/backups/omp-ui/Caddyfile.before-omp-ui` (0600, не в репозитории). Восстановите её, выполните reload Caddy через штатный service unit и затем остановите/отключите только `ompweb-ui.service`. Основной `ompweb.service` не перезапускайте. Для проверки конфигурации нужен реальный `/usr/local/bin/caddy` с DuckDNS-модулем и существующее service environment; apt-бинарник `/usr/bin/caddy` этого модуля не содержит.
